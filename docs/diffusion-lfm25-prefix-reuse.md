# CPU prefix reuse для diffusion LFM2 MoE

Проверено 12 ноября 2026 года на той же уменьшенной FP32-модели, что и
[исходный CPU-прототип](diffusion-lfm25-prototype.md). Полный 24B checkpoint
не использовался. Веса и модель не менялись: 40 слоёв, 30 ShortConv,
10 attention, 64 эксперта top-4, width 32, 5 888 000 параметров.

## Что сохраняется

Флаг `kinetic diffuse --prefix-reuse` один раз на **каждый блок** выполняет
каузальный префикс через все слои и сохраняет:

- В attention — уже нормализованные и повёрнутые RoPE ключи и значения.
  Canvas-проход проецирует только canvas, с абсолютным смещением позиций
  на длину префикса. Attention читает конкатенацию prefix KV и canvas KV
  в том же порядке суммирования, что и полный пересчёт.
- В ShortConv — окно gated inputs на границе префикса. Каждый canvas-проход
  получает отдельную копию этого окна. Canvas никогда не продолжает состояние,
  оставшееся после предыдущего denoising-прохода.

FFN/MoE префикса также исполняются только при подготовке блока. Выходные
скрытые состояния префикса не нужно хранить на каждом слое: достаточно KV
и окон свёрток. При новом блоке префикс строится заново из полного исходного
промпта и ограниченной истории генерации; `prefix_builds` в JSON показывает
число таких подготовок. Это не постоянный кэш между запросами или блоками.

В library API `Diffusion::prepare_prefix()` возвращает неизменяемый `Prefix`,
заимствующий ровно ту модель, которая его создала. `Prefix::forward()`
выдаёт логиты canvas. `Diffusion::generate_reusing_prefix()` использует тот
же fixed greedy sampler, что и обычный `generate()`. Полный пересчёт остаётся
доступен без флага; ускорение не включается молча.

## Проверка тождественности

Проверка Rust на GGUF включает 9 длин префикса (1/2/3/9/37/63/64/65/257),
canvas 1/16/32/64 и полностью masked, частично masked и полностью открытый
canvas: **108 сравнений логитов побитово**. Короткие префиксы проверяют
границы conv-окна, длины 63/64/65 — границы batch tiles. Последовательность
A → B → A проверяет неизменяемость кэша. Отдельно проверены смена блока,
окно истории, короткий последний блок, один шаг и шагов больше позиций.

CLI-harness сравнивает 8 сценариев, **968 064 логита за 111 проходов**.
У всех логитов совпадают байты F32; максимальная ошибка full/reuse — ноль.
На каждом шаге точно совпадают кандидаты, confidence, порядок коммитов,
mask, canvas до/после, префикс, итоговые ID и число проходов. Проверяется
ровно одна подготовка префикса на каждый блок.

У каждого из 12 бенчмарков начальный контрольный запуск тоже пишет полную
парную трассу. Она сверяется побитово с теми же промптами, окном истории
64 и числом шагов, которые затем измеряются. Поля `bit_identical` и
`logits_compared` каждой строки бенчмарка фиксируют эту отдельную проверку.
Вместе это **20 сценариев, 327 пар проходов и 3 225 984 побитово одинаковых
логита** (968 064 в conformance и 2 257 920 в контрольных трассах бенчмарков).

После рефакторинга полный путь заново проверен через исходный Python-harness:
5 сценариев и 215 424 логита прошли прежний допуск, максимальная ошибка
относительно Python осталась `7.152557373046875e-6`. Таким образом, оптимизация
сверена с полным Rust-пересчётом побитово; перенос Rust/Python по-прежнему
оценивается с FP32-допуском. Ревизия и SHA Python-референса закреплены в
документе исходного прототипа.

## Методика замера

AMD Ryzen 5 9600X (6 ядер / 12 логических процессоров), Windows x64,
шесть потоков Kinetic, release CPU build без CUDA/Vulkan features.
Для каждой строки — исходный контрольный запуск, затем два прогрева
и девять измерений **полной генерации** в одном загруженном процессе.
Стоимость подготовки всех префиксов включена. Загрузка модели,
токенизация и запись трассы исключены. Полный режим и reuse выполняются
отдельными процессами, порядок запуска режимов чередуется между строками.
Приведены медианы; исходные выборки и p10/p90 сохранены в JSON.

Генерируется `2 * canvas + 7` токенов, то есть три блока с коротким последним;
окно добавляемой истории — 64 токена. Сравниваются одинаковые промпты и
настройки, количество токенов и проходов контролируется. Есть строки
для промптов длиной 37 и 257 токенов, для 4 и 8 шагов.

фоновыми задачами Windows; разброс отдельных повторений виден в p10/p90.

## Запуск и воспроизведение

Новая сборка: `D:\LLM\kinetic-diffusion-reuse-cpu.exe`.
Дистрибутив: `D:\LLM\kinetic-dist\diffusion-prefix-reuse-cpu-351554b`.
Старый `kinetic-diffusion-cpu.exe` оставлен на месте: во время обновления
он был открыт отдельным процессом. Основной CUDA launcher также не менялся.

```powershell
& D:\LLM\kinetic-diffusion-reuse-cpu.exe diffuse `
  D:\LLM\models\lfm25-diffusion-cpu-fixture\lfm2moe-diffusion-fixture-f32.gguf `
  --mask-embedding D:\LLM\models\lfm25-diffusion-cpu-fixture\mask.safetensors `
  --prompt-tokens D:\LLM\logs\kinetic-diffusion-prefix-reuse-verified-20261112\verify-c64-s4-p37\prompt.json `
  --canvas 64 --steps 4 -n 71 --prefix-window 8 -t 6 --prefix-reuse
```

Без `--prefix-reuse` та же команда выполняет полный пересчёт.
`--benchmark-runs 9` добавляет массив `benchmark.samples_ms` к JSON-результату;
повторные измерения выполняются без trace IO, даже если контрольный запуск
записывает `--trace-dir`. `--dry-run` не выполняет forward и замеры.

```powershell
dotnet run --file scripts/diffusion-prefix-reuse.cs -- `
  --kinetic D:\LLM\kinetic-diffusion-reuse-cpu.exe `
  --fixture D:\LLM\models\lfm25-diffusion-cpu-fixture `
  --output D:\LLM\logs\kinetic-diffusion-prefix-reuse-recheck `
  --threads 6 --runs 9
```

Утилита BCL, без новых зависимостей; проверена как native file-based C#
на установленном SDK. `--dry-run` проверяет входные пути и печатает план,
`--verify-only` пропускает замеры. Выходная директория должна быть новой
или пустой. В неё сохраняются команды, stdout/stderr, все попарные трассы,
выборки времени и манифест с SHA бинаря/модели/маски/скрипта.

Проверки исходного кода: `cargo fmt --all -- --check`, `git diff --check`,
Clippy CLI со всеми features и `-D warnings`, 308 library-тестов workspace
(4 внешних теста пропущены), 44 теста CLI и 4 GGUF integration-теста diffusion.
Release CPU-сборка выполнена командой
`cargo build --locked --release -p kinetic-cli --no-default-features`.
Проверены `--prefix-reuse --dry-run` и отказ при `--benchmark-runs 0`.
